### <a name="_qmphm5d6rvi3"></a>**Решение**

[CD диаграмма](Task5/Task5-CD.drawio.png)

[C2 диаграмма](Task5/Task5-C2.drawio.png)

1. Формирование предодобренных кредитных предложений (ПКП): главным владельцем данных о кредитных предложениях остаётся кредитный конвейер:  
    - Конвейер по регламенту в нерабочее время запускает процесс формирования ПКП.  
    - Передаёт задачу в кредитный скоринг.  
    - Кредитный скоринг проводит оценку, возвращает результат.  
    - Кредитный конвейер сохраняет информацию и записывает событие в очередь с информацией об условиях и принадлежности предложения.  
    - Сервис bid-service разбирает очередь и сохраняет данные в БД. В дальнейшем является точкой получения и управления условиями предложений для клиентов.  
2. Для процесса согласования заявок переиспользованы компоненты депозитного процесса: Request-service — API для взаимодействия, Camunda request-processing на Camunda с отдельным процессом для кредитных заявок, notification-service для уведомлений.  
3. Переиспользованы процессы работы с кол-центрами аналогично депозитным процессам.  
4. Для интернет-банка предложен отдельный микросервис (на будущее в качестве BFF) для обработки кредитных интерфейсов. Это позволит гибко управлять серверной нагрузкой, учитывая различия в пользовательской активности по депозитам и кредитам.  
5. Для обеспечения требования 14 заложена авторизационная модель в API Gateway.

### <a name="_bjrr7veeh80c"></a>**Альтернативы**  
1. Получение предодобренных кредитных предложений:

    1. Запрос из сервиса интернет-банка в кредитный конвейер  
        - Плюсы: низкая задержка, прямой доступ, мало точек отказа  
        - Минусы: нагрузка на кредитный конвейер, сложности с идентификацией клиента  

    2. Запрос из сервиса интернет-банка через API Gateway АБС в кредитный конвейер  
        - Плюсы: средняя задержка, дополнительная точка отказа, логика в сервисе интернет-банка  
        - Минусы: API Gateway не предназначен для сложной бизнес-логики (идентификация, отбор предложений)  

    3. Запрос из сервиса интернет-банка через API Gateway АБС и специализированный сервис credit-personalization-service в кредитный конвейер  
        - Плюсы: реализация сложной бизнес-логики, единая точка работы с персональными кредитными предложениями (включая передачу данных в кол-центр)  
        - Минусы: много точек отказа, высокая задержка  

    4. Передача готовых данных о предодобренных кредитных условиях в систему онлайн-обслуживания через очередь  
        - Плюсы: низкая связность, ограниченный набор данных (при компрометации доступ только к условиям, а не всей кредитной истории)  
        - Минусы: дублирование данных  

Для обеспечения изоляции, низкой связности и безопасности данных выбран последний вариант. В качестве раздающего сервиса выбран bid-service как единая точка управления условиями предложений и ставками.  

2. Кредитный отдел мог бы заниматься обработкой заявок в АБС, но процесс работы с кредитной заявкой конвейере требуют дополнительной проработки.

 Задачи для целевой архитектуры на расширение:  
- Отдельная система аутентификации, авторизации и второго фактора;  
- Отдельная система/группа компонентов для отправки СМС-коммуникаций клиентам с обработкой ретраев;  
- Микро-фронтенд для интернет-банка.

### **Недостатки, ограничения и риски**  
1. Отдельная система для работы менеджеров кредитного отдела. Менеджеры обрабатывают заявки в кредитном конвейере по требованию разделения доступа (требование 14). Можно перевести процесс полностью в АБС, используя авторизационную модель API Gateway.  
2. Аутентификация в интернет-банке — небезопасное и сложно масштабируемое решение. Нужно спланировать проектирование отдельной системы аутентификации, авторизации и двухфакторной аутентификации.  
3. Интернет-банк интегрирован с SMS-шлюзом по HTTPS. Риски: при недоступности шлюза требуется механизм отказоустойчивости. Специализированная группа компонентов могла бы эту функцию взять на себя.  
4. Единый фронтенд для интернет-банка несёт риск снижения доступности при перегрузке.
